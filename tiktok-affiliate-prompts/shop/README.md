# ระบบหลังบ้านขาย “599 Prompt ก๊อปวาง” (99 บาท) · Shop Backend

Cloudflare Worker + D1 + R2 · รับเงิน **พร้อมเพย์เข้าบัญชีร้านโดยตรง (ไม่ต้องมี Payment Gateway)** ·

## ลองดูของจริงก่อน (พรีวิว ไม่ต้องมีคีย์)
```bash
cd shop && node demo-server.mjs 3000     # เปิด http://localhost:3000
```
หน้าขาย → กรอก/ไม่กรอกอีเมล → กด **ซื้อเลย** → เห็น **QR พร้อมเพย์ (payload จริง แต่ใช้เบอร์ตัวอย่าง)**
→ กด **🧪 จำลองสแกนจ่าย ฿99** → ระบบแจ้งโอน + แนบสลิปจำลอง + ร้านอนุมัติ → ส่งอีเมล (จำลอง)
→ **ปุ่มดาวน์โหลดโผล่อัตโนมัติ** · เข้าหลังบ้านที่ `/admin` ด้วย token `demo-admin`

หน้า **`/links`** (คลังลิงก์หรับแปะในไบโอ TikTok): รวมทางไปแจกฟรี/ซื้อ/แคมเปญ 30 วัน + QR 2 อัน + ปุ่มแชร์
(QR สร้างจากฝั่งเซิร์ฟเวอร์ จึงใช้ได้แม้ปิด JS · เลือกสี QR ได้ด้วย `?c=%23FF3D00`)

หน้า **`/order`** (หน้ากดสั่งแบบสั้น — สำหรับลิงก์ไบโอ/โฆษณาที่อยากให้ซื้อเลย): เปิด `http://localhost:3000/order`
→ กรอกอีเมล → กด **“กดสั่ง — จ่ายพร้อมเพย์ ฿99”** → QR ขึ้นทันที → แนบสลิป/วางข้อความ QR → ระบบอนุมัติ + **ปุ่มดาวน์โหลดขึ้นเอง (ไม่ต้องรีเฟรช) และ PDF ถูกโหลดให้อัตโนมัติทันทีที่อนุมัติ**
(กลับเข้าหน้าเดิมด้วย `?order=…` ได้ · ใช้ API ชุดเดียวกับหน้าขายเดิมทั้งหมด)

หน้าแจกของแถม (เก็บอีเมล): เปิด `http://localhost:3000/free` → เห็น 5 ชุดแรกโดยเปิดเต็มชุดเดียว
→ กรอกอีเมล + ติ๊กยินยอม → **ปลดล็อกครบ 5 ชุดบนหน้าจอทันที** + ส่งอีเมล (จำลองในเดโม)
→ เข้า `/admin` การ์ด **“อีเมลผู้สนใจ”** เห็นรายชื่อ/สถิติ + ดาวน์โหลด CSV ได้

## FLOW ทำงานอย่างไร (รับเงินเข้าพร้อมเพย์ตรง ๆ)
1. ลูกค้ากด **ซื้อเลย** → `POST /api/checkout` **ต้องมีอีเมล** (เก็บเป็นฐานลูกค้า + ใช้ส่งลิงก์โหลดอัตโนมัติ)
2. Worker สร้างออเดอร์ใน D1 (`pending`) + สร้าง **payload QR พร้อมเพย์** (มียอด 99.00 ฝังอยู่) + เรนเดอร์เป็น SVG เองในเครื่อง
3. ลูกค้าสแกน QR ด้วยแอปธนาคาร → โอนเข้าบัญชีร้าน (เงินเข้าพร้อมเพย์ร้านทันที ไม่มีค่าธรรมเนียม)
4. ลูกค้ากด **“ฉันโอนแล้ว — ตรวจอัตโนมัติเลย”** → `POST /api/order/:id/report` แนบ **สลิป (รูป)** หรือ **วางข้อความ QR จากสลิป**
5. **ระบบตรวจให้เองอัตโนมัติ** (EasySlip v2) → ถ้ายืนยันครบ (ยอดตรงเป๊ะ + ผู้รับเป็นช่องทางรับเงินของร้าน + สลิปไม่ซ้ำ) จะ mark `paid` + **ส่งลิงก์โหลดเข้าเมลลูกค้าทันที** + แจ้งร้านว่า “อนุมัติอัตโนมัติแล้ว” (ไม่ต้องมีคนกดอะไรเลย)
   - ไม่ครบเงื่อนไข/ตรวจไม่ได้ → ค้าง `reported` พร้อม **เหตุผล** เก็บไว้ให้หลังบ้านเห็น และแจ้งร้านทางอีเมล (ร้านกด “อนุมัติ” เองได้ 1 คลิก)
   - ปิดโหมดอัตโนมัติได้ด้วย `AUTO_APPROVE=0` · ไม่ตั้งคีย์ `EASYSLIP_API_KEY` = ตรวจเองที่หลังบ้าน (พฤติกรรมเดิม)
6. หน้าขายเห็น `paid` → `GET /paid?order=` คืน **signed download URL** (HMAC, อายุ 24 ชม.)
7. `GET /api/download/:token` → เช็ค token + สถานะ paid → stream **ไฟล์รุ่นล่าสุด** จาก R2 + นับรอบโหลด
   - ลิงก์ทุกอัน (เก่า/ใหม่) ชี้ที่ไฟล์ปัจจุบัน ไม่ผูกกับเวอร์ชัน → **ออกรุ่นใหม่แล้วลูกค้าเก่าได้ไฟล์ใหม่จากลิงก์เดิม** (ดูหัวข้อ “แพ็กอัปเดตตัวเอง”)
8. ลิงก์หมดอายุ/หาเมลไม่เจอ → `POST /api/retrieve` ขอลิงก์ใหม่ (จำกัด 5 ครั้ง/ชม./อีเมล)
9. ยืนยันการชำระเงินครั้งแรก → เพิ่มอีเมลนั้นเข้า **ทะเบียนลูกค้า** (`subscribers`) อัตโนมัติ (ใช้แจ้งเวอร์ชันใหม่ในอนาคต)

**ทำไมต้องมีขั้นตอน “แจ้งโอน/สลิป”:** พร้อมเพย์บัญชีบุคคลไม่มี webhook แจ้งเงินเข้า (มีแต่บัญชี merchant/เกตเวย์)
วิธีมาตรฐานของร้านเล็กคือให้ลูกค้าแจ้งโอน/แนบสลิป แล้วร้านตรวจกับแอปธนาคาร — ระบบนี้ทำขั้นตอนนั้นให้อัตโนมัติมากที่สุด

## โหมดอัตโนมัติเต็มรูปแบบ (ตรวจสลิป + อนุมัติ + ส่งเมลเอง)
เปิดใช้ด้วยการตั้งคีย์ผู้ให้บริการตรวจสลิป 1 ตัว — **ไม่ต้องแก้โค้ด**

| ตั้งอะไร | ผล |
|---|---|
| `EASYSLIP_API_KEY` (secret) | เปิดการตรวจสลิป/ยอดเงินอัตโนมัติ (EasySlip API v2 — `POST https://api.easyslip.com/v2/verify/bank`) |
| `AUTO_APPROVE=1` (ค่าเริ่มต้น) | ยืนยันครบเมื่อไร → อนุมัติ + ส่งลิงก์ให้ลูกค้าทันที · `0` = ตรวจให้แต่รอคนกดอนุมัติ |
| `REQUIRE_EMAIL=1` (ค่าเริ่มต้น) | บังคับกรอกอีเมลตอนซื้อ → ทุกออเดอร์มีอีเมลเก็บไว้และได้รับลิงก์อัตโนมัติ |
| `AUTO_VERIFY_MAX_ATTEMPTS=5` | ลองตรวจต่อออเดอร์สูงสุด 5 ครั้ง (กันลูกค้ายิงสลิปมั่วจนโควตาตรวจหมด) |
| `SLIP_MATCH_AMOUNT` / `SLIP_MATCH_ACCOUNT` | ส่งเงื่อนไขยอดตรง + บัญชีผู้รับที่ลงทะเบียนไว้ให้ผู้ให้บริการตรวจให้ |

**อนุมัติเองเฉพาะเมื่อครบทุกข้อ** (ไม่ใช่มั่ว): 1) ตรวจสำเร็จ · 2) ยอดในสลิปตรงกับยอดออเดอร์เป๊ะ · 3) ผู้รับเป็นช่องทางรับเงินของร้าน (ตรงกับช่องทางที่ออเดอร์นี้เลือกก่อน ถ้าไม่ได้บันทึกไว้จึงเทียบทุกช่องทาง) · 4) `isDuplicate=false` และไม่เคยใช้ `transRef` นี้กับออเดอร์อื่น

**รับได้ทั้ง 2 ทางเข้า:** แนบรูปสลิป (`image`, ≤ 4MB) หรือวางข้อความ QR จากสลิป (`qr_payload` เป็น JSON/multipart ก็ได้) — ข้อความ QR เร็วกว่าและไม่ต้องอัปโหลดรูป

**ตรวจไม่ผ่าน/ผู้ให้บริการล่ม:** ระบบไม่เดา — ค้าง `reported` + เก็บ `verify_note` (เหตุผล) และ `verify_attempts` ให้หลังบ้านเห็น · ถ้าพบว่าโควตาหมด/คีย์ผิด/ผู้ให้บริการไม่ว่าง จะแจ้งเตือนร้านทางอีเมลทันที

> ⚙️ **ตั้งค่าให้ `matchAccount` ทำงานได้เต็มที่:** ในหน้าเว็บ EasySlip ต้องเพิ่ม “บัญชีรับเงิน” ของร้านไว้กับคีย์นั้นด้วย — **วิธีการที่เอกสาร EasySlip ระบุคือลงทะเบียนผ่าน API** `POST https://api.easyslip.com/v2/bank-accounts` (`bankCode`, `bankNumber`, `nameTh`, `nameEn`, `type=NATURAL`) ด้วยคีย์ของสาขานั้น (เอกสารไม่ระบุเมนูในเว็บให้กรอกเอง) ถ้ายังไม่ได้เพิ่ม ระบบจะยังตรวจได้ด้วยการเทียบกับ `PROMPTPAY_OPTIONS` ที่ตั้งไว้ (ผลลัพธ์เหมือนกันสำหรับร้านที่มีช่องทางเดียว)
>
> 🧪 **ตรวจก่อนเปิดขาย (ไม่กินโควตาเลย):** `node tools/check-easyslip.mjs` — อ่านคีย์จาก `.secrets/EASYSLIP_API_KEY` หรือ env, พิมพ์แค่ hash สั้น ๆ ของคีย์ (ไม่โชว์ค่าคีย์), แยกให้ออกระหว่าง “คีย์ผิด (401 INVALID_API_KEY)” กับ “คีย์ถูกแต่ถูกระงับ/โควตาหมด (403 BRANCH_INACTIVE/QUOTA_EXCEEDED/IP_NOT_ALLOWED)” และบอกโควตาที่เหลือ · โหมดทดสอบสลิปจริง `--slip <ไฟล์>` / `--payload '<ข้อความ QR>'` จะตัดสินแบบเดียวกับร้าน (ยอดตรง · ผู้รับตรงช่องทาง · ไม่ซ้ำ · มีเลขอ้างอิง) แล้วบอกว่าจะอนุมัติเองหรือติดข้อไหน
>
> 🔑 **ขอคีย์ที่ไหน:** **พอร์ทัลนักพัฒนา `https://developer.easyslip.com`** (สมัครที่ `/auth/sign-up` → ยืนยันอีเมล → **Applications → Create New Application** → เลือกแพ็ก (ทดลอง 7 วัน / Start ฿99=250 ครั้ง) → คัดลอกคีย์จากหัวข้อ **Credentials** ของ application) · คีย์มีหน้าตาเป็น **UUID** เช่น `8f3a1c2e-…` ไม่มี prefix `esk_` · ใช้จริงบน production ต้องผ่าน **KYC**
>
> 🌐 **สำคัญ:** **ปิด IP allow-list หรือตั้งเป็น `*` ใน Application Settings** — Cloudflare Worker ไม่มี IP ขาออกคงที่ ถ้าเปิดไว้จะโดน 403 `IP_NOT_ALLOWED` (ระบบจะค้างออเดอร์ไว้ให้ตรวจเอง + แจ้งเตือนร้าน ไม่ใช่การขายพัง)

## แพ็กอัปเดตตัวเอง — “ซื้อครั้งเดียว ได้ทุกเวอร์ชันใหม่” (ไม่ต้องพูดคำว่าสมาชิก)

ลูกค้าไม่ได้ซื้อ “ไฟล์” แต่ซื้อ **แพ็กที่ตามอัปเดต** — พอเจน prompt ชุดใหม่ ลูกค้าคนเดิมได้ของใหม่ทันทีโดยไม่ต้องซื้อซ้ำ
และเราไม่ต้องมีระบบสมาชิก/ต่ออายุเลย เพราะทำงานบนกลไกง่าย ๆ 2 อย่าง:

1. **ลิงก์ดาวน์โหลดไม่ผูกกับเวอร์ชัน** — ทุกโทเคนชี้ไปที่ `PDF_OBJECT_KEY` (ไฟล์ปัจจุบัน) → ออกรุ่นใหม่แล้ว **ลิงก์เดิมของลูกค้าทุกคนโหลดไฟล์รุ่นล่าสุดให้เอง**
   (ตอบหัว `x-pack-version` มาด้วยว่ากำลังโหลดรุ่นไหน · ชื่อไฟล์ที่โหลดก็มีเลขรุ่นต่อท้าย)
2. **ทะเบียนลูกค้า (`subscribers`) + อีเมลแจ้งรุ่นใหม่** — ยืนยันการชำระเงินครั้งแรก = เข้าทะเบียนอัตโนมัติ · ออกรุ่นแล้วกดแจ้งทีเดียว ระบบส่งอีเมลให้ทุกคนที่ซื้อแล้ว โดย**ไม่ส่งซ้ำ**คนที่แจ้งรุ่นนี้ไปแล้ว และ**ไม่ส่ง**ให้คนที่กดยกเลิกรับอีเมล

| ขั้น | ทำอะไร |
|---|---|
| 1 | เจน prompt ชุดใหม่: `cd ..` → `node tools/gen-prompts.mjs` (เขียน `prompts/<N>.md` + `index.csv` + `prompts-<N>.csv`) → `node tools/gen-prompts.mjs --check` · กลับมา `shop/` แล้ว `node tools/build-free-sample.mjs` |
| 2 | แก้ **`pack-version.mjs`** ที่เดียว (version/prompts/niches/updated_at) → `.venv/bin/python build_pdf.py` (เวอร์ชันบนปก PDF อ่านจากไฟล์นี้) |
| 3 | เข้า `/admin` → การ์ด **“แพ็ก & เวอร์ชัน”** → เลือก PDF + ใส่เลขรุ่นใหม่ + “มีอะไรใหม่” → ติ๊ก “แจ้งลูกค้าคนเดิม” → **ออกรุ่นใหม่** |

ระบบจะ: เก็บสำเนาไฟล์รุ่นนี้ไว้ที่ `versions/prompt-pack-v<รุ่น>.pdf` · ตั้งรุ่นใหม่เป็น `is_current` · เขียนทะเบียนพร้อม `sha256`
· ส่งอีเมล “มีเวอร์ชันใหม่” ให้ลูกค้า**ทีละชุด** (ค่าเริ่มต้น 20 คน/ครั้ง หลังบ้านวนส่งต่อจนจบเอง) · แสดงความคืบหน้าและจำนวนคนที่ยังค้าง

**ทำเองผ่าน curl ก็ได้** (ตั้ง `T=$ADMIN_TOKEN`, `H=https://โดเมนร้าน`):
```bash
# ออกรุ่นใหม่ + เริ่มแจ้งลูกค้าชุดแรก
curl -s -X POST "$H/admin/pack/publish" -H "Authorization: Bearer $T" \
  -F file=@build/prompt-pack.pdf -F version=1.5 -F prompts=649 \
  -F notes="เพิ่ม 50 ชุดใหม่ หมวดของใช้ในบ้าน" -F notify=1 | jq .notify

# ส่งต่อจนจบ (remaining = 0) — เรียกซ้ำได้ปลอดภัย ไม่ส่งซ้ำ
while :; do R=$(curl -s -X POST "$H/admin/pack/notify" -H "Authorization: Bearer $T" -H 'content-type: application/json' -d '{}'); echo "$R" | jq -c '{sent,remaining,done,stalled}'; echo "$R" | jq -e '.done or .stalled' >/dev/null && break; done
```

| ตัวแปร | ค่าเริ่มต้น | ทำอะไร |
|---|---|---|
| `UPDATE_LINK_TTL_HOURS` | `720` (30 วัน) | อายุลิงก์ในอีเมลแจ้งรุ่นใหม่ (ลิงก์ในใบเสร็จยังใช้ `DOWNLOAD_TTL_HOURS`) |
| `PACK_NOTIFY_BATCH` | `20` | ส่งอีเมลกี่คนต่อครั้ง (1–50) — กันชนเพดานเวลา/อัตราการส่งของ Worker และอีเมล |

**ข้อควรรู้**
- ตาราง `pack_versions` / `subscribers` และคอลัมน์ `orders.last_download_version` ถูกสร้างให้อัตโนมัติตอนเรียก API ครั้งแรก (`ensureSchema`) — ไม่ต้องรัน migration เอง
- อีเมลแจ้งรุ่นใหม่มี **List-Unsubscribe + one-click** และลิงก์ยกเลิกที่ลงชื่อผูกกับอีเมล — กดแล้วหยุดทั้งอีเมลการตลาดและอีเมลแจ้งรุ่นใหม่ (แต่ลิงก์โหลดของที่ซื้อแล้วยังใช้ได้)
- เลขรุ่นซ้ำจะถูกปฏิเสธ (`409`) — ถ้าแค่เปลี่ยนไฟล์เดิมโดยไม่ออกรุ่น ให้ใช้ `/admin/product`
- ส่งไม่ออกจะ**ไม่**มาร์คว่า “แจ้งแล้ว” → เรียกซ้ำได้ทีหลัง และถ้าส่งไม่ออกเลยแต่ยังมีคนค้าง API จะตอบ `stalled: true` (ไม่ให้หน้าบ้านวนลูปไม่จบ)
- `GET /api/pack` เปิดเผยแค่เวอร์ชัน/จำนวนชุด/ประวัติ — ไม่มีจำนวนลูกค้า/คีย์/ความลับ

## โดเมนร้าน (จำเป็นถ้าจะส่งอีเมลลิงก์โหลด)
ดู **`DOMAIN.md`** — ชื่อโดเมนที่ตรวจแล้วว่ายังว่าง, ราคาต่อปีของแต่ละผู้ให้บริการ, เงื่อนไข `.co.th`/`.in.th` และ DNS record ที่ Resend ต้องใช้
สรุปที่แนะนำ: `promptpack.shop` (ว่าง) ซื้อที่ Porkbun แล้วตั้ง `APP_ORIGIN` / `MAIL_FROM` / `NOTIFY_EMAIL` เป็นโดเมนนั้น

## ส่งอีเมล (Resend)
1. สมัคร https://resend.com → **API Keys** → `wrangler secret put RESEND_API_KEY`
2. **Domains** → verify โดเมน แล้วตั้ง `MAIL_FROM` ให้ตรง (เช่น `599 Prompt ก๊อปวาง <no-reply@yourdomain.com>`)
   - ระหว่างทดสอบใช้ `MAIL_FROM="599 Prompt ก๊อปวาง <onboarding@resend.dev>"` (ส่งได้เฉพาะอีเมลเจ้าของบัญชี)
3. อีเมลล่มไม่ทำให้การยืนยันชำระเงินพัง — ออเดอร์ยังเป็น `paid` และดูสลิป/ส่งลิงก์เองได้จากหลังบ้าน
4. ตั้ง `NOTIFY_EMAIL` = อีเมลร้าน เพื่อรับแจ้งเตือนทันทีที่มีลูกค้าแจ้งโอน

## ตารางคำสั่งซื้อ + จัดการสินค้า (ระบบหลังบ้าน)
เปิด `/admin` แล้วใส่ `ADMIN_TOKEN` หรือเรียกตรง:
```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" https://<โดเมน>/admin/orders
```
คืน JSON: id, email, ยอด, status, reported_at, slip_key, trans_ref, verify_source, รอบโหลด, เวลาชำระ + สถิติ
สถานะ `reported` = มีลูกค้าแจ้งโอนรอตรวจ · หลังบ้านมีปุ่ม **อนุมัติ/ปฏิเสธ** และลิงก์เปิดดูสลิป

### การ์ดใน `/admin` (จัดการสินค้า/ออเดอร์/ของแถม ในหน้าเดียว)
| การ์ด | ทำอะไรได้ |
|---|---|
| **แดชบอร์ดออเดอร์** | ดูรายได้ · รอตรวจสลิป · รอชำระ · โหลดกี่ครั้ง · กด **อนุมัติ/ปฏิเสธ/ลบ** ต่อออเดอร์ · เปิดดูสลิปจริง |
| **ไฟล์สินค้า (PDF)** | อัปโหลด/เปลี่ยน PDF ที่ลูกค้าโหลด (`POST /admin/product`) — **ไม่ต้อง deploy** ลิงก์เดิมของลูกค้าทุกคนชี้ไฟล์ใหม่ทันที |
| **แพ็ก & เวอร์ชัน** | ออกรุ่นใหม่ + **แจ้งลูกค้าทุกคนที่ซื้อแล้ว** ทางอีเมล (`/admin/pack/publish` + `/admin/notify`) · ดูทะเบียนลูกค้า · ดาวน์โหลด CSV |
| **อีเมลผู้สนใจ (leads)** | ดู/ลบอีเมลที่รับของแถมจาก `/free` · ดาวน์โหลด CSV |
| **ไฟล์สินค้า (PDF)** | ตรวจสถานะไฟล์ใน R2 (ขนาด + sha256) |

### ดาวน์โหลด PDF อัตโนมัติ (ไม่ต้องกดเอง)
ทันทีที่ระบบ **อนุมัติการชำระเงิน** (ตรวจสลิปอัตโนมัติผ่าน EasySlip หรือร้านกด “อนุมัติ” เอง) หน้าเว็บจะ:
1. เปิดปุ่ม **⬇ ดาวน์โหลด PDF ทันที** ขึ้นมา และ
2. **โหลดไฟล์ PDF ให้เองโดยอัตโนมัติ** — ลูกค้าไม่ต้องกดอะไรเลย (มี guard กันโหลดซ้ำตอน poll/refresh · ทำงานที่หน้า `/` `/order` และ `/thank-you`)
พร้อมกันนั้นระบบยัง **ส่งลิงก์ + ใบเสร็จเข้าอีเมล** ซึ่งใช้ได้ 24 ชม. (ถ้าโหลดอัตโนมัติถูกบล็อกโดยเบราว์เซอร์ ปุ่มบนหน้ายังกดได้ปกติ)

## หมายเหตุสำคัญ
- **ราคา:** `PRICE_SATANG=9900` (99 บาท) — ยอดนี้ถูกฝังใน QR (`54` = `99.00`) และใช้ตรวจสลิปอัตโนมัติ · **หน้าเว็บทุกหน้าดึงราคาจาก `/api/health` เอง** (เปลี่ยน `PRICE_SATANG` แล้วขึ้นราคาใหม่ทั้งเว็บ ไม่ต้องแก้ HTML)
- **ลิงก์โหลด:** อายุ 24 ชม. ต่อออเดอร์ โหลดกี่รอบก็ได้ภายในอายุ (`DOWNLOAD_TTL_HOURS`)
- **สลิป:** เก็บใน R2 ที่ `slips/<order_id>` เข้าถึงได้เฉพาะผ่านหลังบ้าน (ต้องมี `ADMIN_TOKEN`)
- **กันสลิปซ้ำ:** เลขธุรกรรม (`trans_ref`) ในคอลัมน์เดียวไม่ซ้ำกัน (unique index) ใช้สลิปเดิมกับสองออเดอร์ไม่ได้
- **PDF สินค้า** สร้างจากไฟล์ Markdown จริงของแพ็ก (`build_pdf.py`) — แก้เนื้อหาแล้วรัน `.venv/bin/python build_pdf.py` แล้วอัปโหลดทับจากหลังบ้าน (`POST /admin/product`) หรือ `wrangler r2 object put …` · ปกหน้า/ปกหลังสร้างด้วยโค้ดใน `build_pdf.py` (ดำ-ส้ม) ไม่ต้องใช้ไฟล์ภาพภายนอก
- **หน้าปกหลังมี 3 อย่างที่แก้ได้จากตัวแปรต้นไฟล์ `build_pdf.py`:** `SHOP_EMAIL` (อีเมลร้าน) · `SHOP_URL` (ลิงก์ร้าน — ใช้ทั้งข้อความชวนเพื่อน, บรรทัดร้าน/ซื้อซ้ำ และ **QR**) · `VERSION` · ตัว QR สร้างจาก `qr.mjs` ตัวเดียวกับที่เว็บใช้ (ต้องมี `node` ตอน build; ถ้าไม่มีจะข้าม QR ไปแต่ PDF ยังสร้างได้)
  - ✅ **`SHOP_URL` = `https://kopwang.com` แล้ว** (17 ต.ค. 2026 หลังผูกโดเมน) — สร้าง PDF ใหม่ 477 หน้า 1,554,803 ไบต์ · **ตรวจ QR บนปกหลังถอดออกมาได้ `https://kopwang.com`** · อัปโหลดทับใน R2 ผ่าน `POST /admin/product` และเช็ค `sha256` ของออบเจกต์ใน R2 ตรงกับไฟล์ในเครื่อง · ถ้าแก้ `SHOP_URL`/`VERSION` อีก ให้ build ใหม่แล้วอัปโหลดทับทุกครั้ง
- **ก่อน live จริง:** เติมชื่อผู้ขาย/ช่องทางติดต่อจริงในหน้า terms/refund/privacy (ตอนนี้เป็น `support@example.com` ตัวอย่าง)
- **ยังใช้ Payment Gateway ได้:** ตั้ง `PAYMENT_PROVIDER=omise` + คีย์ Omise แล้วระบบกลับไปใช้ flow charge + webhook เดิม
